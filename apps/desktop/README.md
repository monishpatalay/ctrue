# Ctrue desktop

Electron overlay for permitted assistance and mock interview practice. Run `npm run dev:desktop` from the root with the API running. For browser-only UI QA: `npm exec -w @ctrue/desktop vite -- --host 127.0.0.1`. Enable the clearly labeled local demo in the app only when the backend runs `DEMO_MODE=true`.

Copy `.env.example` to `.env`. Public service URLs are embedded into the main-process bundle during `build`, so Finder-launched packaged apps do not rely on shell environment variables. Provider secrets remain in the backend. The website hands off a short-lived code; Electron redeems it for its own Ctrue credential (10-minute access token, 30-day rotating refresh token), encrypts it with OS secure storage, refreshes through the API, and revokes it on sign-out. No plaintext fallback is supported.

The app starts billing only after Start, Resume, capture, or generate starts an active session. Pause/End stop audio and generation. Heartbeats maintain a server lease; a disconnected/crashed app stops billing when the lease expires (15 seconds). Hide keeps the session active; use Pause to stop credits. Screen and microphone capture require user consent. The microphone is optional; system audio capture can include other applications.

Packaged local builds: `npm run package:mac` creates an unsigned directory/zip; `npm run package:win` creates an NSIS installer. A Windows installer built from macOS needs Wine for installer generation; validation and signing must happen on Windows. Supply Apple/Windows signing credentials through electron-builder's documented environment variables for release. macOS notarization requires Apple developer credentials and signing; local artifacts are not notarized. No production release is claimed by building an unsigned artifact.

## Capture limitations to test on devices

Electron 39+ uses macOS CoreAudio Tap for system audio. `NSAudioCaptureUsageDescription` is included in packaged builds. Terminal/IDE launched development apps may lack that parent-process permission declaration and produce a silent/ended audio track; the app checks track readiness and shows an actual input level. Test a packaged build on macOS 14.2+ with an audible source. Input level confirms samples, not transcript-provider availability. See [Electron desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer).

The main window is an ordinary solid window. Shortcuts open a small see-through pop-up that floats above other apps without taking focus: listen (answers what is asked on the call), screenshot (answers what is on the current screen at once), and hide/show. The pop-up has a follow-up box. Capture protection covers both windows and is on by default (switch it off in Preferences). On macOS 27 a protected window was absent from Electron's own screen capture in a local test; each meeting app still has to be checked. It cannot guarantee invisibility: macOS ScreenCaptureKit can capture protected windows; Windows capture exclusion also depends on the capture path. See [Electron BrowserWindow content protection](https://www.electronjs.org/docs/latest/api/browser-window#winsetcontentprotectionenable) and [Microsoft display affinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity). Panic hide is immediate; tray and the same shortcut restore the app.

Before release, manually test Zoom/Teams/Meet screen and window sharing, recording, headphones and speakers, microphone disabled/enabled, denied/revoked permissions, source window closed, device changes, multiple displays and DPI scaling, network loss and reconnect, system sleep, long sessions, hotkey conflicts, capture exclusion on each OS, signed login links, expired handoffs, exhausted credits, and signed update installation. These are physical-device acceptance checks; automated tests cannot establish capture exclusion or proctoring evasion.

Updates remain disabled until `CTRUE_SIGNED_RELEASE=true` and an HTTPS `CTRUE_UPDATE_FEED_URL` are embedded in a signed build. The updater surfaces failures and asks to restart after downloading. Publishing the feed, notarization, Windows signing, and real-device checks are release prerequisites.
